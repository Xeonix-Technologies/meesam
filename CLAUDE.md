# Meesam (ميسم) — engineering rules

Meesam is Xeonix Technologies' trademark-management platform (owners, agencies, staff).
This file is the standing instruction set for every Claude Code session in this repository.
The specification documents in `docs/` are the authority; when code and a document disagree,
the document wins and the discrepancy is reported to the Founder, never silently "fixed" in code.

## Ruled architecture (do not re-decide)

- TypeScript end to end: `apps/web` (Next.js App Router), `apps/worker` (Node), shared `packages/*`.
- `apps/embeddings` is the only Python service (FastAPI; DINOv3 + SigLIP 2 + perceptual hash). Nothing else in Python.
- PostgreSQL 18 with pgvector on Railway. Drizzle ORM; migrations are plain SQL files in `packages/db/migrations`, reviewed, never regenerated destructively.
- Queue = PostgreSQL job table (`SELECT … FOR UPDATE SKIP LOCKED`). No Redis, no external queue.
- Documents (POA, certificates, publications) live in S3-compatible buckets; never on a volume, never in the database.
- One Dockerfile per service; configuration only through environment variables; nothing Railway-specific in code.
- Relays (Founder ruling 27 Nov 2026): a registry whose site answers only networks inside its own country is fetched through a small server of Meesam's own in that country (an ordinary forward proxy with a fixed address; not a service of this repository). The source names its relay (`fetch_spec.via`); the relay's address and sign-in are worker configuration (`FETCH_RELAY_<NAME>`). Never a rented anonymising proxy or VPN; the fetcher keeps its own name, the re-use gate and the robots rule.
- Web uses the pooled connection string (`DATABASE_POOL_URL`); worker and migrations use the direct one (`DATABASE_URL`).

## Non-negotiable product rules

1. **Multilingual by construction.** Every user-facing string goes through `packages/i18n` (English and Arabic now; languages are data, more later). RTL is a first-class layout, not a patch. No hard-coded UI text, dates or number formats.
2. **Row-level security on every tenant table.** Access is enforced in PostgreSQL policies, with the application setting the session context; the app layer is a second line, never the only one.
3. **Every change to a record is audited** (who, when, what, from which account) and the other side (owner ↔ agency) is notified.
4. **All deadlines are computed from the registry profile.** Never hard-code a period, a stage name or a status wording; each registry carries its own calendar block, timers and wording. Day ends 23:59 registry-local time; no rollover of the last day. Where a period is unverified the user must enter the deadline; the system supplies no default.
5. **Nine-stage lifecycle** (item 42): pre-filing; filing and examination; acceptance, publication and opposition; appeals; registration; post-registration recordals; renewal, grace and expiry; challenges to a registration; enforcement. Terminal statuses sit inside the stage where the mark ended; there is no separate "closed" stage.
6. **Advisory checks only** on data entry: warn, never block saving.
7. **Watch:** no manual upload of publications — fetchers download them, and the fallback on a failed download is automated too. One temporary exception (Founder ruling 19 Nov 2026): a source the watch operations lead has switched to "collected by hand", because its site refuses the fetcher, takes a file added by the lead in the Operations Console, checked and stored like a fetched one. Do not widen it: no upload for any other source, role or audience, and it ends per source when the site accepts the fetcher. A trial on staging only (Founder, 26 Nov 2026, not yet ruled for production): a file e-mailed to Meesam's publications address waits in the Publications inbox until the lead adds it to a source collected by hand or discards it; the route is off wherever `INBOUND_MAIL_KEY` is unset, and it must stay unset on production until he rules. Human verification of AI-extracted marks stays on per registry until retired by ruling. Alerts are per registry and per account; never merged across a mark family or shared between accounts. Comparison (Founder rulings 22 Nov 2026, replacing the class gate and three bands of MSM-PRD-02 and ruling R6): the class is information shown on the alert, never a gate or a weight; four bands, Very high 90–100, High 80–89, Medium 60–79 (these three alert and e-mail), Low 40–59 (listed on the trademark's Watch tab only); a shared whole word counts (80% as the first word of both, else 70%) and small words such as "La", "The", "ال" are skipped. Every figure and word list is configuration (`watch.engine_config`, `watch.threshold`), never a literal in code. Reading (Founder ruling 22 Nov 2026): a bulletin whose entries carry printed codes ((210), (731), (540), (511), (510)) is read from the file's own text by rules, without the AI reader (Türkiye first); the codes, labels and section headings are data on the source (`fetch_spec.read`), a mark read this way that is complete and in the office's own list is accepted without a person where the source's setting says so (`fetch_spec.read.accept`; ruled for Türkiye 22 Nov 2026), the incomplete ones wait in the reviewer's queue. An alert is raised also where the opposition period has already ended; the decision is the owner's (Founder ruling 22 Nov 2026).
8. **Vault file naming:** `regno_serial_DDMMYY_TYPE.ext` with the 14 three-letter type codes (APP, OAC, RSP, PUB, OPP, ORC, REN, DOU, ASG, LIC, CNA, POA, LGR, OTH), plus IMG for the mark's own image (Founder ruling 18 Nov 2026; a 15th code, set by the image upload, not offered in the document list). Registry and country codes are WIPO ST.3.
9. **Pricing engine** implements the price list in force exactly: **Price List v1.0** (Founder ruling 21 Nov 2026; it replaces the Business Model v0.1 list). One fee buys docketing and the watch for one mark at one registry. List price AED 480 at 10 years remaining; introductory price AED 370 only for records paid while the offer is open; 10% of the full price less per year; floor AED 195 at 4 years or less (the introductory 5-year step also stays AED 195). No free states: a new mark pays AED 100 at filing (reminders, no watch), credited toward the full price at the certificate or when the watch is switched on, not refunded; an existing registered mark pays by years remaining when added. AED 150 flat per additional or watch-only registry; AED 100 per class added. UAE buyers see the VAT-inclusive total. Renewal price, pilot terms, the offer's end date and the list's effective date are open: until ruled, the pilot stays "everything free". Prices are configuration (`core.price_list`), dated and versioned, never literals in code; a new list is a new version, never an edit of an old one. Bulk import (Founder rulings 27 Nov 2026): the agency loads its own portfolio; a "Client" column names the agency's client on each row (the agency's own list, `core.client`, never an account); 5,000 rows per file (configuration, `IMPORT_MAX_ROWS`); no documents with the rows. Uploading is free, the use of the uploaded information is not: an existing mark added in bulk or by hand is kept but not active, and until it is activated Meesam shows its name, number and client only (no dates, no reminders, no calendar feed, no watch). The account requests activation once the mark has a clear image and, if it is registered, its certificate (the fee is calculated from the certificate's expiry date: Meesam reads the certificate and holds activation until its expiry date, its filing date and its number agree with the record's (so one certificate serves one record), and asks for a clearer copy when it cannot read it; Founder rulings 28 Nov 2026; when the certificate's number is the record's, the record's filing, registration and expiry dates are taken from the certificate, audited as the user's own change, at the upload or when the number is corrected; a reading never changes the record's number); the mark goes to the basket, where several marks are paid together; any user except a Viewer may do so. Until a payment provider is connected, checkout completes only while the pilot is free. A mark that was never activated can be removed by the administrator of the account it belongs to (Founder ruling 28 Nov 2026): it leaves every page and its number is free again, the row and its audit history are kept; an activated mark is closed by a stage change, never removed.
10. **Invoicing entity** is a configuration value (`INVOICE_ISSUER`), currently Xeonix Technologies, the contracting party (Founder ruling 21 Nov 2026; before that Wahaat Investment L.L.C.).
11. **Staff surfaces:** Meesam System Admin and the Watch Operations Console are separate areas behind a staff role. Human support exists only for technical and payment issues; everything else is self-service and AI-assisted.
12. **Registries are never login users.** A registry is a data source and, later, a data partner.
13. **Data (Founder rulings 21 Nov 2026, from "Data Management and Use v0.1" items 10.1, 10.2, 10.4, 10.5, 10.9, 10.11, 10.12).** What registries publish and what accounts enter are kept in separate areas, matched but never merged: a customer's correction never changes the published data, and a difference is shown as an advisory note. Every published fact carries its source. Meesam does not offer a public trademark search or public mark pages, does not sell raw extracts or contact lists, does not use one account's records to benefit another account, and makes no first contact that cites the publication issue. The other items of that document (10.3, 10.6–10.8, 10.10, 10.13) are planned work or open, not rules. Publications page (Founder ruling 26 Nov 2026): a signed-in owner or agency may see the list of a registry's bulletins and download each file as published, only for a source the watch operations lead has switched on with a stated basis (`publication_source.shown_to_accounts`; the UAE first); it is never public and never a search, and it is off wherever it has not been switched on.

## Working conventions

- Branches: `develop` → staging (Railway autodeploy), `main` → production. Feature branches from `develop`; pull requests get a Railway PR environment.
- Commits: conventional prefixes (`feat:`, `fix:`, `chore:`, `docs:`), present tense, one concern each.
- Never commit secrets. `.env*` files are ignored; Railway variables are the only source of configuration.
- Tests run in CI (`.github/workflows/ci.yml`) before Railway deploys (Wait for CI is enabled on the services).
- When a specification point is ambiguous, implement the narrowest reading, tag it `// RULING NEEDED: <question>` and list it in the PR description for the Founder.
- Write "Section", never the § sign, in any text shown to users or written to documents.
